# Лог HTTP-запросов

Кратко: входящие HTTP-запросы и ответы пишутся в регистр сведений **Лог HTTP запросов**. Запись встроена в конвейер обработки и может быть переопределена.

Раньше подсистема обрабатывала запрос и отдавала ответ, но не сохраняла пару «запрос / ответ» в данных. Теперь каждый проход конвейера фиксируется: метод, ресурс, тело запроса, код состояния и тело ответа. Ошибки записи лога не ломают HTTP-ответ — они уходят в журнал регистрации платформы.

## Регистр `ЛогHTTPЗапросов`

Синоним: **Лог HTTP запросов**. Независимый, периодичность — секунда. Собственных форм и команд нет: список и запись открываются стандартными командами платформы.


| Вид       | Имя                    | Назначение                                |
| --------- | ---------------------- | ----------------------------------------- |
| Измерение | `HTTPСервис`           | Ссылка на `Справочник.HTTPСервисы`        |
| Измерение | `ИдентификаторЗапроса` | Строка 36 символов (UUID)                 |
| Ресурс    | `Метод`                | HTTP-метод                                |
| Ресурс    | `Ресурс`               | Относительный URL                         |
| Ресурс    | `Запрос`               | Текстовое представление входящего запроса |
| Ресурс    | `Ответ`                | Текстовое представление ответа            |
| Ресурс    | `КодСостояния`         | HTTP-код ответа                           |


Программный интерфейс менеджера:

- `ЗафиксироватьЗапрос(Контекст)` — создаёт запись по измерениям и заполняет метод, ресурс и запрос.
- `ЗафиксироватьОтвет(Контекст)` — по тем же измерениям дописывает ответ и код состояния.

Обе процедуры работают в привилегированном режиме. Если нет сервиса или идентификатора — выход без записи.

Справка объекта: `InformationRegisters/ЛогHTTPЗапросов/Ext/Help/ru.html`.

## Конвейер

В `ОбработчикHTTPСервисЗапроса` добавлены этапы (и в `src/cfe/`, и в демо `src/example/`):

`Инициализация` → `РегистрацияЗапроса` → `ПроверкаПравДоступа` → … → `ФормированиеОтвета` → `РегистрацияОтвета`.

**РегистрацияЗапроса**

1. Берётся идентификатор: заголовок `X-Request-ID` длиной 36 символов или новый UUID.
2. Ищутся обработчики из `HTTPСервисЗапросыПереопределяемый.ПриДобавленииОбработчиковРегистрацииЗапроса`.
3. Если своего обработчика нет — вызывается `РегистрыСведений.ЛогHTTPЗапросов.ЗафиксироватьЗапрос`.

**РегистрацияОтвета** — то же через `ПриДобавленииОбработчиковРегистрацииОтвета`; стандарт — `ЗафиксироватьОтвет`.

Идентификатор доступен на обработке запроса: `ОбработчикЗапроса.ИдентификаторЗапроса()`. В контексте поле `ИдентификаторЗапроса` задаётся в `HTTPСервисЗапросыСлужебный.НовыйКонтекст()`.

## Переопределение

В `HTTPСервисЗапросыПереопределяемый` (расширение и демо):


| Процедура                                     | Когда                         |
| --------------------------------------------- | ----------------------------- |
| `ПриДобавленииОбработчиковРегистрацииЗапроса` | Своя запись входящего запроса |
| `ПриДобавленииОбработчиковРегистрацииОтвета`  | Своя запись ответа            |


Формат строки тот же, что у остальных обработчиков: `HTTPСервис`, `Обработчик`, `ВПривилегированномРежиме`, `ВТранзакции`. Служебные выборки: `ОбработчикиРегистрацииЗапроса()` / `ОбработчикиРегистрацииОтвета()`.

## Права

- **ЧтениеHTTPСервисов** — просмотр регистра, без интерактивного редактирования полей записи.
- **ИзменениеHTTPСервисов** — чтение и изменение регистра.

Запись из конвейера идёт в привилегированном режиме, поэтому лог пишется и без интерактивных прав на регистр.

## Подсистема `HTTPСервисы`

У подсистемы задана картинка раздела: общая картинка `HTTPСервисы` (`CommonPicture.HTTPСервисы`). Она отображается в панели разделов командного интерфейса.
